## Design Context

### Users
Multi-role internal tool used daily by students (requesting tutoring sessions), tutors and coaches (managing their schedule and availability), teachers (approving requests, overseeing allocations), and admins. All are affiliated with The King's School (@kings.edu.au). Used on both laptop and phone — responsive design is non-negotiable.

### Brand Personality
Institutional but approachable. Clean and functional without being sterile. The school's existing palette is navy + sky blue, which signals trust and education. Three words: **clear, dependable, unhurried**.

### Aesthetic Direction
Light mode — used in daytime school/office contexts by students and staff on school devices. Functional product UI aesthetic, not a marketing page. Typography should be legible at small sizes in table and list contexts. Layout should prioritise information density done tastefully — this is a scheduling tool, not a landing page.

Anti-references: No AI slop (gradient text, glassmorphism, hero metric cards, cyan-on-dark, bounce easing). No heavy decorative elements. No side-stripe borders on list items (banned pattern). No identical card grids everywhere.

### Design Principles
1. **Function over form** — every visual element should serve the user's task, not decorate the page
2. **Role-aware clarity** — different roles see very different data; the UI should never feel overwhelming or ambiguous about what action to take
3. **Responsive without compromise** — mobile users (students between classes) need the same capabilities as desktop users, just adapted
4. **Institutional trust** — use the school's navy/blue palette consistently; avoid anything that looks playful or consumer-facing
5. **Accessibility as baseline** — WCAG AA minimum; interactive elements must be keyboard-navigable and clearly labelled
